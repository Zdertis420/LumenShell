# Research: Bar Customization and Styles

Facts about Quickshell 0.3.2 come from reading the installed type descriptions (`/usr/lib/qt6/qml/Quickshell/**/*.qmltypes`) and the current code of Features II and III. Items marked **Spike** are not settled by reading and become the first tasks of the implementation. Each has a fallback, so the plan does not depend on the outcome.

Read from the type descriptions: `PanelWindow` has `margins`, `mask` (a `Region`), `exclusionMode`, `exclusiveZone`, `aboveWindows` and `focusable`. `niri msg layers` lists the layer surfaces per output (namespace, keyboard interactivity), so a smoke test can count surfaces. This machine has three outputs, one of them rotated (1080x1920), which is useful for vertical checks.

## R1. Interface version

- **Decision**: The interface becomes **1.2**. The change is additive: (a) a setting can have `"default": null`; (b) the bar's slot gains members. No manifest field is added, removed or reinterpreted. The scan accepts `api` up to 1.2. A module that declares 1.2 on a 1.1 shell is refused with the required and available versions by the existing rule.
- **Why a bump at all**: Items that read the new slot members (`vertical`, `maxLength`, `font`, ...) must be refused on a shell that does not provide them, and the example and built-in items declare 1.2 for that reason. Items declaring 1.1 keep working because the slot members they read are unchanged.
- **Alternatives**: No bump (a 1.1 item that uses the new members on an old shell would fail at run time instead of being refused).

## R2. Where defaults from tokens come from: `default: null`

- **Decision**: A setting rule may have `"default": null`. It means "unset": `api.settings.values.<key>` is `undefined`, the setting appears in the merged schema without a `default`, and the module falls back to a token (for example `api.style.spacing.sm`). A user value must still match the rule; `null` is not accepted from the user file (delete the key to reset). It is allowed for `string`, `integer`, `number` and `boolean` rules.
- **Rationale**: FR-016 asks that a later global override of a Style token reaches the bar. Copying today's token values into `module.json` would freeze them. A sentinel number (`-1`) would also work but takes one valid value away and makes every size setting carry a magic value. Null keeps `0` valid (margin 0, border 0) and makes "not set" a visible state in the schema and in `lumen modules show`.
- **Cost**: Both Go programs and `Modules.qml` learn the rule (a few lines each) and a fixture test covers it.
- **Spike R5**: confirm that an unset key survives the config helper, the merged schema and `api.settings.values` (as `undefined`, not `"null"` or `0`). **Fallback**: sentinel `-1` with `min: -1` (and `0` for the font size, which cannot be zero), documented as "use the token".
- **Alternatives**: A `tokens` object in the slot that items merge by hand (puts the work in every item); defaults copied into manifests (breaks FR-016).

## R3. One panel per screen for solid and islands

- **Decision**: Solid and islands use the single `PanelWindow` that the bar already has per screen, now anchored by the edge (`top`, `bottom`, `left`, `right`), with `margins` for the outer margin. Its cross size is `thickness + margin`, and the along size is the full screen length. Solid draws one rectangle. Islands draw nothing in the window itself, and draw three rounded rectangles (one per non-empty place); the window's input `mask` is the union of the three, so the gaps let the pointer through (FR-003).
- **Why not a window per island**: Each place would need its own surface, its own reservation and its own item ownership, and items would be recreated on a style change (FR-005). One window with a mask keeps item ownership in one place.
- **Space reservation**: The panel keeps `exclusionMode: Auto` (setting `exclusiveZone` switches the mode to Normal, as found in Feature III R8a).
- **Spike R3**: (a) with `margins` set, does `Auto` reserve `thickness + margin` or only the window's size; (b) can the anchors change live (top to left) without recreating the window, so items are kept; (c) does the `mask` region make the gaps click-through on niri. **Fallbacks**: (a) set the margin through a transparent edge of the window instead of `margins` (the window is `thickness + margin` thick and the drawn shape is inset); (b) recreate the window on an edge change, so the items are recreated once, which the spec allows ("not more than once"); (c) draw islands as three windows only if the mask does not work, at the cost of three surfaces per screen.

## R4. Frame style surfaces

- **Decision**: The frame is the strip panel (the same window as in solid, colored with the frame role) plus up to three **border panels**, one per remaining side, each anchored to its side, `frameBorder` wide, colored with the frame role, each reserving its own space. The rounded inner corners are four small **corner pieces**: each is a window of `frameRadius x frameRadius`, anchored to one corner with margins equal to the strip and border sizes there, no reservation, empty input mask, drawing the area between the corner and a quarter circle in the frame color with `QtQuick.Shapes`. Border panels and corner pieces are created by `LazyLoader`s that are active only in the frame style (and only when their width or radius is above zero), so other styles carry nothing extra.
- **Layer**: border and corner surfaces are in the same layer as the bar (`Top`), so a fullscreen window hides them like it hides the bar. Windows never go under reserved space, and the corner pieces cover only the part of the window area that is in the rounded corners.
- **Cost**: at most 8 small surfaces per screen in the frame style (strip, 3 borders, 4 corners), and none in the others.
- **Spike R4**: check on niri that (a) the strip, borders and corner pieces meet with no seam at 1.0, 1.25 and 1.5 scale, (b) corner pieces sit above the windows, (c) the layout survives plugging a screen in and out. **Fallback**: one full-screen, input-less overlay per screen that draws the whole frame as one shape (outer rectangle minus a rounded inner rectangle), while the strip and border panels only reserve space; memory cost is one full-screen buffer per screen.
- **Alternatives**: Draw the frame only with the strip and borders and leave the inner corners square (rejected: the rounded look is the point of the style).
- **R4a. Corner blocks instead of corner pieces (fix, 2026-11-08).** A pixel check of the owner's screenshot (frame on the bottom edge) showed that the four screen corners were not frame-colored: (0,0), (3,3), (7,7) and (3,1046) had the wallpaper color, while the strip and the sides were right. Cause: the compositor lays a layer surface out inside the space that earlier surfaces in the layer reserved, so the top panel and the strip started 8 px in from each side and the side panels stopped at the strip, and the small corner pieces (16 by 16, at the inner corners) did not reach the screen corners. **Decision**: the four pieces become corner **blocks** that start at the screen corner, do not take part in the reservation (`ExclusionMode.Ignore`, which does not shrink with the others' zones), and cover the whole corner square: reserved width of that side plus the radius, by reserved height at that end plus the radius. A block is drawn in the frame color except for the quarter disc of the rounded inner corner (one `Shape` with two sub-paths and the odd-even fill rule). With a radius of 0 the block is a plain rectangle, so the band is unbroken for every border width and radius, including 0; a block of no size is not created. **Rationale**: any gap the layout leaves is at most the width of the other panels' zones at one end, which is inside the corner block, so the result does not depend on the order the compositor lays the surfaces out in. **Alternatives**: order the creation of the panels so that the layout comes out right (rejected: it depends on compositor behavior we do not control); extend each panel with `exclusiveZone` set by hand and a negative zone for the others (rejected: a negative zone gives up the reservation); one full-screen overlay (the R4 fallback, rejected for its buffer per screen). **Spike result still to check by hand**: the blocks sit above the panels and the seams are invisible at scale 1.25 and 1.5.
- **R4a result (checked 2026-11-08 with an in-process screen capture).** A throwaway Quickshell config captured one output through `ScreencopyView`, saved the frame to a temporary file, and a script sampled pixels (the file was deleted; nothing went to the clipboard or the screenshot folder). With the fix, the pixels at all four screen corners (and 2 and 5 px in from them) are frame-colored for the frame on each of the four edges, for a radius of 0, and for a border of 3 with a radius of 30. The first version drew each block as one rectangle with the quarter disc cut out by the odd-even fill rule; at the top-left corner only, the renderer left the cut-out filled (the other three were right), which an ASCII map of the pixels showed. The disc shares edges with the rectangle, which this renderer mishandles in that orientation, so a block is now two simple shapes that do not overlap (the L-shaped band, and the spandrel between the inner corner and the arc), and all four corners show the right arc.
- **R4b. No margins on the border panels (fix, 2026-11-09).** Two owner screenshots (frame on the bottom edge and on the left edge) showed a gap of about 20 px along a side, between a side panel and the corner block next to the strip: on the bottom edge the left and right panels ended at y 1006 while the corner blocks start at y 1027 (1080 - 37 - 16); on the left edge the top panel started at x 75 while the corner block ends at x 53. Cause: the panels across the bar had `margins` equal to the strip's space (37), but niri already lays a later surface out inside the space an earlier one reserved, so the panel was moved 37 + 37 = 74 px from the edge. **Decision**: the border panels have no margins at all; their position along the screen comes from the compositor's layout of the reserved zones. **Rationale**: whatever order the surfaces are laid out in, a panel then either starts right after another panel's zone (no gap) or overlaps it (hidden, same color); the largest possible shortfall is one border width at a screen end, and the corner block of that corner is `border + radius` wide, so it covers it. **Alternative**: keep the margins and drop the reservation from the strip's side (rejected: depends on the layout order). **Check**: a pixel capture as in R4a on all four edges, sampling along every side, not only at the corners.
- **Corner block count.** Blocks have a size when the border or the radius is above 0 (also for a radius of 0). With both at 0 there is no corner to fill and only the strip is left, as the smoke test checks. A frame with a border of 0 on a top bar rounds the two bottom screen corners against the bare screen edge, as the spec says ("the rounded inner corners stay").

## R5. Spike: unset settings through the pipeline

See R2. The first task of the implementation writes a fixture module with `"default": null` settings of each type and checks, in the Go tests and with `lumen modules show` in the smoke test, that: the manifest is valid; the merged schema has no default; the config helper returns the key only when the user sets it; reset removes the override; `api.settings.values` gives `undefined` when unset.

## R6. Fonts

- **Decision**: Font settings: `fontFamily` (string, unset = token family), `fontSize` (integer 1 to 96, unset = `font.body`), `fontWeight` (a string of `thin`, `light`, `regular`, `medium`, `semibold`, `bold`, `black`; unset = `regular`), `fontItalic` (boolean). The bar resolves them once into `look.font` and gives the result to items as `slot.font`. A family that is not installed is detected with `Qt.fontFamilies()` and falls back to the token family with one warning that names the key and the family (FR-014). A weight the family lacks is handled by the font system, which picks the nearest face, and needs no check.
- **Spike R6**: confirm that `Qt.fontFamilies()` is callable from a module and cheap, and how it treats a family that is an alias (`sans-serif`, `monospace`). **Fallback**: skip the installed check and let the font system substitute silently, with a note in the documentation, which loses one warning but keeps every other behavior.
- **Rationale**: Doing the check in the bar keeps it next to the use; a Go check would need the font list from `fc-list`, which is a new dependency.

## R7. Color roles and opacity

- **Decision**: Each colored part has a role setting and, for backgrounds, an opacity: `backgroundRole`/`backgroundOpacity` (solid strip), `islandRole`/`islandOpacity`, `frameRole`/`frameOpacity`, `textRole`, `focusRole`, and for the popup `popupBackground` and `popupBorder`. A role is a string whose `enum` lists the 16 roles of `Theme.qml` (primary through outline); the config helper rejects any other name with an error that names the key, and the bar falls back to that part's default role (surface, surface, surface, onSurface, primary, surfaceContainer, outline). The result is a color from `api.theme.roles` with the alpha set; it follows the theme live because it is a binding.
- **Agreement test**: `bar_settings_test.go` reads the role names from `Theme.qml` and from every manifest that lists them and fails if they differ, so a new role is added in one place and flagged elsewhere.
- **Alternatives**: Free text color names or hex values (forbidden: principle II); a role list copied only into docs (drifts).

## R8. Vertical layout, the slot and legacy items

- **Decision**: `layout.js` works on lengths along the bar. Its signature becomes `fit(lengths, available, opts)` with `opts = {itemGap, placeGap, placePadding}`; the old call shape `fit(widths, available, gap)` is kept working by treating a number as `{itemGap: gap, placeGap: gap, placePadding: 0}`, so the existing tests pass unchanged. A place adds `2 * placePadding` when it holds at least one shown item (islands). The holder for an item gets `along = clamp(item length, maxLength)` and `cross = thickness`; the item's length is `implicitWidth` on a horizontal bar and `implicitHeight` on a vertical one.
- **Slot (interface 1.2)**: added to the slot, all reactive: `vertical`, `maxLength` (the most length the bar gives this item), `font` (`{family, pixelSize, weight, italic}`), `itemPadding`, `itemRadius`, `textRole`, `focusRole`. Kept: `edge`, `thickness`, `maxWidth`, `screenName`, `place`, `focused`, `popup`. `edge` gains `left` and `right`. `maxWidth` means "the most width the item can use": `maxLength` on a horizontal bar and `thickness` on a vertical one, so an item written for Feature III that elides its text at `maxWidth` shrinks to the thickness on its own, and the rest is clipped by the holder (FR-024).
- **Rationale**: This gives old items a sensible look on a vertical bar with no change, and gives new items the facts they need.
- **Spike R8**: with the default thickness (font 13 + 2 x 12 = 37 px), do the vertical forms fit: clock `HH` over `mm`, sound `Vol` over `45%`, battery `Bat` over `85%` (and `Chg` over `85%` while charging)? **Fallback**: a larger default thickness on vertical bars only (a documented style default), or the percent without a label.

## R9. Keyboard: no change in this feature

- **Decision** (owner, 2026-11-08): This feature adds and changes no key handling. Keyboard interactivity stays explicit: a module reacts to the keyboard only through its own IPC command that the user binds in the compositor (the bar's `lumen modules call bar focus` is such a command and works as in Feature III on every edge). Modules that obviously need the keyboard, such as a launcher, may take it themselves. Every popup closes on Escape, as in Feature III. The sound item's keys stay as they are.
- **Consequence**: On a vertical bar the focus command uses the same keys as on a horizontal one (the keys of Feature III), so keyboard navigation along a vertical bar is not tuned in this feature.
- **Governance**: This is the owner's policy, and it is now Principle VIII of the constitution (v2.0.0): a module reacts to the keyboard only through its own command bound in the compositor, keyboard-input modules such as a launcher may take focus when opened, and every popup closes on Escape. Principle VI no longer has a keyboard rule. This feature meets VIII: the bar's `focus` command is unchanged, nothing else takes focus, and popups close on Escape.
- **How it is checked**: `niri msg layers` prints the keyboard interactivity of each layer surface (seen in this machine's output: `Keyboard interactivity: none` for the wallpaper surface). The smoke test asserts that every surface of the bar, in every style and on every edge, reports `none` before the focus command, a non-`none` value only for the surface that holds the focus while the command's session is active, (the return to `none` after Escape is a by-hand check, because key events cannot be injected in the test environment, as found in Feature III); and that the popup host reports exclusive focus only while a popup is open and `none` after it closes (driven by a module command). **Spike R3/R4 note**: the first spike tasks also record what `niri msg layers` prints for the bar's surfaces, so the check can be written against real output; if the text differs from the wallpaper's format, the check adapts to what is printed.
- **Alternatives**: Axis-following arrows for focus and cross-axis volume keys (the earlier plan; dropped by the owner).

## R10. Geometry: defaults per style and limits for small screens

- **Decision**: A pure function in `geometry.js` takes the resolved settings and the screen size and returns the sizes the windows use and a list of warnings. Defaults for unset sizes:

| Size | solid | islands | frame |
|------|-------|---------|-------|
| thickness | font size + 2 x spacing.md | same | same |
| margin | 0 | spacing.sm | 0 |
| padding (ends of strip, or inside each island) | spacing.sm | spacing.md | spacing.sm |
| item gap, place gap | spacing.sm | spacing.sm | spacing.sm |
| radius (strip or island) | 0 | radius.full | 0 |
| frame radius | not used | not used | radius.lg |
| frame border (other sides) | not used | not used | spacing.sm |

  The solid column reproduces the bar of Feature III (SC-002). Limits: along each axis the reserved sizes (thickness + margin, border) may take at most half of the screen; the frame radius at most half of the smaller side of the inner area; a radius above half of a shape's smaller side is drawn fully round and is not reported (FR-015); anything limited gets one warning that names the key.
- **Rationale**: The rules need the live screen size, so they run in QML, but as a pure function they are unit tested without a shell, like `layout.js`.

## R11. Popup surface

- **Decision**: `popup.js` places a popup next to the item on the side facing into the screen for each of the four edges, with the same rules as before (shifted to fit, never over the item, limited to half of the screen). The popup frame takes `popupRadius` (unset = `radius.md`), `popupPadding` (default 0, as today), `popupBorderWidth` (default 1) and the roles `popupBackground` and `popupBorder`. The content is inset by the padding.
- **Alternatives**: Popup settings owned by each item (rejected: the host places and frames the popup, so the host owns its frame).

## R12. What the tests enforce for FR-017

- **Decision**: `no_magic_values_test.go` already rejects bare numbers in `*.qml`. It is extended with the property names that carry visual values (`radius`, `margins`, `leftMargin` and the other margin properties, `spacing`, `padding` properties, `font.pixelSize`, `border.width`, `implicitWidth`/`implicitHeight` additions) so a literal there must come from a token, a setting or a documented constant. The existing exemption by named constant stays. The bar's files are scanned the same way as the items.
- **Rationale**: This is the "test that finds visual values fixed in code" that the constitution's gate and FR-017 ask for.

## R13. Memory and CPU across style and edge changes

- **Decision**: The smoke test cycles the style (solid, islands, frame) and the edge (four values) 100 times, compares memory after the first cycle with memory after the last (limit 12%, the margin settled for the bar reload in Feature III), checks that no item was recreated more than once and that no extra surfaces remain (counted with `niri msg layers`), and measures idle CPU in each style over the same window as the existing check.
- **Risk**: The battery item's per-instance UPower cost known from Feature III still applies to bar reloads, not to style changes (items are kept).

## R14. Documentation and the example

- **Decision**: `docs/bar.md` gets a section for each style (with a configuration example and the frame's look), a table of every setting with default and range, the vertical bar, the slot facts, and the keyboard rule. `docs/module-api.md` gets the 1.2 notes (unset defaults, slot facts, "additive, no migration"). `examples/hello-bar-item/` reads `slot.vertical`, `slot.font`, `slot.itemPadding` and `slot.textRole`, and shows `default: null` for its own optional setting, so a new author can copy both.

## Measurements

### Spikes (2026-11-08, this machine: niri 26.04, DP-2 1920x1080 with the probe window tiled 1890x1050, Quickshell 0.3.2)

The probe is the tile size of a window on DP-2 (`niri msg --json windows`): it shrinks by exactly the space a panel reserves.

- **T001 / R3 (a) margins with `Auto`: PASS.** A 40 px panel with a 10 px margin reserved 50 px (tile 1050 to 1000 high on top, 1890 to 1840 wide on the left); with margin 0 it reserved 40. So `exclusionMode: Auto` reserves `thickness + margin`, and no fallback is needed.
- **T001 / R3 (b) live anchor change: PASS.** The same `PanelWindow` was re-anchored top, left, bottom, right every 4 s (anchors and margins are bindings): the reserved space followed each time (1000, 1840, 1000, 1840 and back) with no recreation and no warnings. The edge change keeps items.
- **T001 / R3 (c) input mask: NOT VERIFIABLE HERE.** Pointer events cannot be injected in this environment (no `ydotool`; `wtype` is keyboard only), so click-through in the gaps cannot be tested automatically. The islands use `mask: Region` as planned; the click-through check is a by-hand step in the quickstart (step 3). Fallback if it fails by hand: three windows for islands.
- **`niri msg layers` output** (needed by T017, T026 and T064): per output, per layer, one `Surface:` block with `Namespace: "<name>"` and `Keyboard interactivity: none` (or another value while a surface holds focus). Quickshell panels default to the namespace `quickshell` in the `Top layer`; `WlrLayershell.namespace` sets another, so the bar's surfaces get distinct namespaces (`lumen-bar`, `lumen-bar-border-<side>`, `lumen-bar-corner-<corner>`, `lumen-bar-popup`) and smoke tests can count them. The text was seen with a spike panel (keyboard `none`).
- **T002 / R4 frame surfaces: PASS for structure, reservation and input.** A strip (top, 40) plus left, right and bottom borders (8) plus four corner pieces (16, empty `Region`, `Shape` fill) gave 8 surfaces in the `Top layer`, all `Keyboard interactivity: none`, and a probe tile of 1874x1002 (= 1890-16 by 1050-40-8): the three borders and the strip reserve exactly their widths and the corner pieces reserve nothing. Panels must be created with `Variants` (a `Repeater` does not create windows). Not checked automatically (screenshots would capture the user's screen): seams at scale 1.25 and 1.5, drawing of the corner arcs, stacking against fullscreen windows, output hot-plug. These are by-hand steps in the quickstart (step 3). Fallback if seams show: one input-less overlay per screen.
- **T003 / R5 unset settings: PASS with two small changes.** The `config` helper puts a rule's `default` into the defaults tree as is, so a null default reaches `api.settings.values` as `null` (not `undefined`); modules read it with `??`, which treats both alike. The `modules` program needs: `default: null` accepted for the four scalar types and refused for `stringlist` (`checkSetting` currently reports "is required"/validates the default as a value), and the merged schema must not print `"default": null` (`schema.go` copies `default` verbatim). A user `null` already fails the type check in the helper. No sentinel is needed. `contracts/module-manifest-1.2.md` says "`undefined`"; read it as "`null` or `undefined`".
- **T004 / R6 installed fonts: PASS with a rule.** `Qt.fontFamilies()` works in a module and takes 1 ms (100 families here). It lists real family names only: the generic names `sans-serif` and `monospace` (the Style defaults) and `DejaVu Sans` (not installed here, `fc-match` gives Nimbus) are not in it. Rule: a family is "installed" if it is in `Qt.fontFamilies()` (case-insensitive) or is one of the generic names `sans-serif`, `serif`, `monospace`, `cursive`, `fantasy`, `system-ui`; anything else gets the one warning and the token family. `JetBrains Mono` is not installed under that name here (it is `JetBrainsMono Nerd Font`), which is a good real test of the warning.
- **T005 / R8 vertical forms: PASS at the default thickness.** Widths at font 13 (px): `HH` 19, `mm` 22, `Vol` 19, `45%` 26, `100%` 34, `Vol off` 37 (too wide), `off` 15, `Bat` 20, `Chg` 24, `85%` 26, `Bat +` 31, `+85%` 34, `Fri 06` 33. All fit the 37 px default thickness except `Vol off`. Decided forms: clock `HH` over `mm`; sound `Vol` over `45%`, muted `Vol` over `off`; battery `Bat` over `85%`, charging `Chg` over `85%`. The widest, `100%` at 34 px, leaves 3 px, so the vertical forms use no cross padding.

### Resource checks (2026-11-08, T060 and T061, this machine: three outputs, Quickshell 0.3.2)

- **100 style and edge changes in a row (SC-010):** the baseline after a warm-up pass through all 12 combinations was 674,376 kB, and after 100 more changes 582,044 kB (it went down). Idle CPU over 2 minutes was 0.01% in solid, 0.01% in islands and 0.02% in frame (limit 1%); the existing check without the bar's styles gave 0.02%. The planned window was 5 minutes; 2 minutes was used for each of the three styles to keep the run to about 25 minutes in all.
- **A first frame costs memory once.** The first creation of the frame's surfaces raised the shell from about 450,000 kB to about 610,000 to 680,000 kB on three outputs (7 extra small windows per output, so roughly 7 to 11 MB per window: the toolkit keeps what it allocates for a window). It does not grow with later changes: 60 edge flips in the frame style stayed within a few MB of each other. A cheaper frame (borders that also draw the corner arcs, 4 windows per output instead of 8) is possible and is a follow-up if this footprint matters; the cost is also why the smoke baseline is taken after the warm-up pass.
- **Memory leak found and fixed on the way:** the border panels were created with a size of 0 along their length, and each creation left about 4 MB behind. Giving the panels (and the strip) explicit sizes removed it (a run of solid to frame and back, twelve times, grew by 0 instead of 160,000 kB).
- **Reload growth fix (2026-11-09).** `make perf` showed 100 bar reloads growing RSS by +11.8% (+54 MB, linear: +4.9% then +6.5% over the two halves) against the limit of 12%, with PSS +22% (a smaller base; the budgets are in RSS). Cause as above: every load used a new URL (`?r=N`), so the engine kept one compiled copy per reload. **Change**: `modules scan` now returns a `fingerprint` (hash of the names, sizes and modification times of the module's files, hidden directories skipped); `Modules.qml` keeps the URL revision per `id|fingerprint` and reuses it while the files are unchanged, so a reload of an unchanged module keeps no second copy, and an edited module gets a new revision and is compiled again. A load that failed forgets its revision, so a retry compiles again (the engine may have cached the error). `TestScanFingerprint` covers the fingerprint. **Result (`make perf`, same day)**: 100 reloads: -1.4% RSS (455,572 -> 448,960 kB; halves -1.5% and +0.0%), against +11.8% before; 100 contributor load/unload cycles: -1.8% (they were +1.6% to +4.8%); popup cycles +0.0%. Idle CPU 0.00% to 0.03% in each style (30 s windows). Smoke section 13 (an edited item is loaded again after a reload) passes.
- **Bar reload (SC-010, limit 12% as decided in Feature III):** 100 reloads grew memory by 13.1% and 11.8% before and 11.4% and 10.4% after calling the engine's garbage collection after an unload (`Modules.qml`). The growth comes from the compiled QML of each reload being kept under its own URL, so it grows with the size of the module's files; real use reloads a few times. Contributor load and unload: +1.5% over 100 cycles. Popups: flat.
- **Two Feature III bugs fixed while building this** (the "flaky" smoke checks of Features II and III): the dropped-items check flipped because a hidden holder made an item read as not visible and the item was dropped, shown and dropped again; and the runtime-error check missed errors when the first `qs log --follow` of the shell exited early and was restarted with `--tail 1`.
- **Still by hand** (cannot be done by the test environment): click-through in the gaps between islands, seams and rounded corners of the frame at scale 1.25 and 1.5, stacking against fullscreen windows, output hot-plug, Escape leaving the bar's focus and closing a popup, and how the three styles look.
