# Tasks: Bar

**Input**: Design documents from `/specs/003-bar/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md. Foundation (`specs/001-foundation/`) and Modules (`specs/002-modules/`) are implemented.

**Tests**: Included. The constitution requires automated tests for backend logic, the plan defines black-box Go tests, a `qmltestrunner` test for the pure QML functions, and a smoke test, and several requirements (isolation, memory, keyboard, popups, hot-plug) can only be shown against a real shell. Test tasks come before the implementation they cover and should fail first.

**Organization**: Grouped by user story. The shared pieces every story needs (interface 1.1 in the `modules` and `config` programs, the contribution registry in the Modules singleton, item resolution) are in Phase 2.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on unfinished tasks)
- **[Story]**: Which user story the task belongs to (US1–US6)

## Path Conventions

Paths are relative to the repository root (see plan.md "Source Code"). Go programs are standalone `package main` under `scripts/src/<name>/` with no `go.mod` and no shared code between programs; they build to `scripts/bin/<name>`. Tests are black-box and live in `scripts/tests/`; run them with `make test`. QML rules from Foundation and Modules apply: no `: void` or `: var` annotations (use `: variant`), no `sed -i` or shell redirection to edit files, no color or spacing literals in module QML (colors from `api.theme`, sizes from `api.style`).
